# 开奖数据来源部署说明

主站自动开奖现在只接受两类来源：福彩/体彩官方接口，以及可选的国内签名采集节点。旧 `huiniao`、`cz89` 仅供 `DrawSourceCheck` 排查，不再单独结算投注。任何来源都必须返回待处理的连续期号、三位合法号码和已到达的开奖时间；官方与节点返回同一期但号码不一致时停止结算。

## 先在现有服务器只读测试

发布代码后，在项目根目录运行：

```bash
php think DrawSourceCheck fc3d 2026307
php think DrawSourceCheck pl3 26307
```

这是只读命令，不修改数据库。发布后应改用最近**已开奖**期号测试；尚未开奖的期号显示无有效结果是正常的。确认“官方接口”两种彩种都能返回与官方公告一致的号码后，再观察下一期自动任务。

若海外服务器无法读取官方接口，可部署国内节点。先在国内节点直接测试官方接口可达性及返回格式，再启用签名转发。官方接口属于公开网页使用的接口，结构和访问策略可能变化，节点不能替代上线验证。

## 国内节点

将本目录的 `index.php` 单独部署到具备 PHP+cURL 的国内 HTTPS 站点。不要把它放在主站网站目录或 Git 可访问目录中。为该站点的 PHP-FPM 配置至少 32 字符的随机 `DRAW_RELAY_SECRET`，且不要将密钥写入仓库、公开网页或截图。

节点只按 `type=fc3d|pl3` 和指定 `period` 读取官方接口，不连接主站数据库；若官方未返回该期，返回 HTTP 404。成功时返回期号、号码、开奖时间、生成时间，以及对这些字段的 HMAC-SHA256 签名。

主站 `.env` 增加：

```ini
[DRAW_RELAY]
URL = https://你的国内节点域名/index.php
SECRET = 与节点相同的随机密钥
```

主站只通过 HTTPS 请求节点，并验证签名、15 分钟时效、彩种、期号、号码格式和开奖时间。节点不是必需的；未配置时主站只使用可用的官方直连结果。

## 上线核对

1. 先备份历史开奖记录，确认当前最新已开奖期号及下一待开奖期号；不要通过修改旧期号来推进页面。
2. 在海外主站和国内节点分别运行只读来源检查，核对两彩种的期号、号码与官方公告一致。
3. 在下一期开奖后检查应用日志中的来源、期号、号码、结算笔数；再核对开奖记录和投注状态。
4. 若两路冲突、接口过期、超时或缺期，系统停止自动结算。由管理员核对官方公告后补录，不能仅凭计划任务显示“Successful”判断已派奖。

## 开奖接口延迟时的重试

开奖时间到了但官方接口还未发布指定期号时，主站保留待开奖状态并保持封盘，**不会把同一期自动顺延到次日**。需要让计划任务持续重试，不能只在晚上固定执行一次 HTTP 请求。

建议在堡垒机计划任务中停用旧的 `triggerAutoDraw` URL 任务，改为使用已配置 PHP 的 CLI 命令：晚上每 5 分钟执行一次，其他时段每 30 分钟执行一次，以覆盖延迟到次日的情况。示例 crontab（将项目路径和 PHP 路径换成服务器上的实际值）：

```cron
*/5 21-23 * * * cd /实际项目根目录 && flock -n /tmp/lottery-autodraw.lock /实际PHP路径/php think AutoDraw >> runtime/log/autodraw_cron.log 2>&1
*/30 0-20 * * * cd /实际项目根目录 && flock -n /tmp/lottery-autodraw.lock /实际PHP路径/php think AutoDraw >> runtime/log/autodraw_cron.log 2>&1
```

`flock` 防止任务重叠。`AutoDraw` 只有两个彩种都处理成功时才返回退出码 0；官方接口未更新时返回非 0，并在下一次计划任务重试。页面读取当前期不会触发采集。若某天官方确认休市，管理员应按官方安排处理期号和封盘时间，不能仅以“接口未更新”推断休市。

本地仓库没有 `thinkphp/console.php`，因此这里完成了 PHP 语法及解析夹具测试，完整命令启动需要在部署了依赖的服务器上核验。
